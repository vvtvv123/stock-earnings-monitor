# Stock Earnings Monitor

## Data contract
This project is a data system for US stock earnings monitoring.
The agent's job is to maintain and advance the data, not the code framework.

- `watchlists/nasdaq_tickers.json` — list of `{ticker, next_earnings_ts}`
- `watchlists/sp500_tickers.json` — list of `{ticker, next_earnings_ts}`
- `data/earnings_history.jsonl`
- `data/upcoming_earnings.jsonl`
- `data/alerts.jsonl`

## Authoritative data sources
### Calendar / next earnings date
- Primary: NASDAQ public API via `finance-calendars` style wrapper
  - Endpoint: `https://api.nasdaq.com/api/calendar/earnings?date=YYYY-MM-DD`
- Fallback: `yfinance.Ticker.earnings_dates` when installed

### Actual earnings numbers
- Primary: SEC EDGAR filings
  - Use `https://www.sec.gov/cgi-bin/browse-edgar?action=getcompany&CIK={ticker}&type=8-K&dateb=&owner=include&count=40`
  - Find the most recent 8-K filing for earnings and parse exhibit/attachment text for EPS, revenue, period, guidance if present
- Secondary: NASDAQ earnings calendar rows (`epsActual`, `revenueActual`, `epsEstimate`, `revenueEstimate`) when available
- Optional: Yahoo Finance / `yfinance` historical tables and `quarterly_financials` when installed

### Historical backfill
- SEC EDGAR bulk filings index / submissions API per company
- Prefer quarterly 10-Q/8-K filings for actuals; use calendar source for estimates if not found in filings

## Data pipelines
### 1. Watchlists
Keep the ticker lists complete and accurate.
Populate from Wikipedia or trusted free sources.
Store as JSON array of objects with `ticker` and `next_earnings_ts` fields.

### 2. Earnings dates population
Use NASDAQ calendar API to find next earnings dates.
Iterate a reasonable lookahead and fill `next_earnings_ts` in both watchlists.

### 3. Upcoming earnings calendar
Extract next earnings dates per ticker.
Persist to `data/upcoming_earnings.jsonl`.
Limit to a reasonable lookahead horizon.

### 4. Historical earnings backfill
Populate `data/earnings_history.jsonl` with historical earnings records.
Do not trash old data on refresh; append or upsert by ticker+period.

### 5. New report ingestion
When a new earnings report lands, read the live report data from SEC EDGAR first.
Store the new record with at least: ticker, period, EPS actual, EPS estimate, revenue actual, revenue estimate, fetched timestamp.

### 6. Growth detection
Compare each new record to prior periods for that ticker.
Flag when there is significant earnings growth via objective criteria:
- EPS actual exceeds EPS estimate by >= 5%
- Revenue actual exceeds revenue estimate by >= 1%
Write flags to `data/alerts.jsonl`.

### 7. Telegram alert
For each alert in `data/alerts.jsonl`, send a concise Telegram message:
- ticker
- matched criteria
- actual vs estimate numbers

## Invariant
All work must be executable with plain `python src/<name>.py`.
No new dependency on FastAPI or other apps unless requested.

## Conventions
- Use `requirements.txt` for dependencies only.
- Use `data/` for JSONL outputs.
- Use `watchlists/` for static ticker lists.
- Do not hardcode credentials. Read from env or `config.yaml`.
- Telegram sending is the Hermes gateway usage here.
- Keep changes minimal and focused.

## Suggested run order
1. `python src/watcher.py --once`
2. `python src/fetcher.py --populate`
3. `python src/fetcher.py --ingest`
4. `python src/scorer.py --emit-alerts`
5. `python src/alert_telegram.py`
