# Stock Earnings Monitor

## Data contract
This project is a data system for US stock earnings monitoring.
The agent's job is to maintain and advance the data, not the code framework.

- `data/earnings_history.jsonl` — append-only actual EPS/revenue per ticker per period; dedup/audit log only, NOT the growth baseline
- `data/alerts.jsonl` — emitted alert records
- `data/cik_tickers.json` — cached SEC ticker->CIK map (regenerable, gitignored)

## Authoritative data sources

### Current-quarter actual EPS + revenue
- Finnhub public API: `https://finnhub.io/api/v1/calendar/earnings?from=YYYY-MM-DD&to=YYYY-MM-DD&token=$FINNHUB_API_KEY`
- Requires `FINNHUB_API_KEY` env var (free tier, signed up by the user; never
  put the key in `config.yaml` or any tracked file).
- Confirmed real schema (2026-07): `symbol`, `date`, `hour` ('bmo'/'amc'/''),
  `quarter`, `year`, `epsEstimate`, `epsActual`, `revenueEstimate`,
  `revenueActual`. All numeric fields are plain numbers, no `$`/`,` cleanup
  needed (unlike NASDAQ's calendar).
- Chosen over the NASDAQ calendar endpoint because NASDAQ has no revenue
  field at all and lags noticeably in posting actuals (verified live: NASDAQ
  showed 0/71 scheduled reports posted on a date where Finnhub already had 52
  actuals).

### Year-ago-quarter baseline (the growth comparison point)
- SEC EDGAR `companyfacts` API: `https://data.sec.gov/api/xbrl/companyfacts/CIK{cik}.json`
- CIK looked up from SEC's official `https://www.sec.gov/files/company_tickers.json`
  (cached to `data/cik_tickers.json`).
- EPS tags: `EarningsPerShareDiluted`, falling back to `EarningsPerShareBasic`.
  Revenue tags: `RevenueFromContractWithCustomerExcludingAssessedTax`,
  falling back to legacy `Revenues`. Only entries spanning ~1 fiscal quarter
  (80-100 days) are used, and only the one whose end-date is closest to
  365 days before today, within a 45-day tolerance.
- **Why EDGAR and not Finnhub for this:** Finnhub's free tier cannot serve
  historical data at all for this purpose. `/calendar/earnings` returns zero
  rows for any date before "now" (tested multiple 2025 ranges, all empty) —
  it's a current/upcoming-only feed, not an archive. `/stock/earnings?symbol=X`
  returns real historical quarters but is hard-capped at the 4 most recent
  (ignores `from`/`to`/`limit`), EPS-only (no revenue), and is consistently
  one quarter short of a true year-ago match for a freshly-reported company.
  EDGAR has genuine free multi-year history for both fields.
- **Known gaps** (log and skip, never fabricate a mismatched comparison):
  foreign private issuers filing IFRS have no `us-gaap` facts at all; some
  filers only have annual figures with no quarterly breakdown; EDGAR's ASC 606
  revenue tag doesn't apply to interest income, so financials (banks) usually
  have no revenue figure at all.

### Upcoming-schedule preview only (not part of alerting)
- NASDAQ public API: `https://api.nasdaq.com/api/calendar/earnings?date=YYYY-MM-DD`
  is still used by `src/watcher.py` purely so a human can glance at what's
  coming up. It is not used to decide when to fetch actuals or to score
  anything.

## Data pipeline

`src/monitor.py` is the single entrypoint, meant to run every minute via cron:

1. Fetch today's Finnhub earnings calendar (US/Eastern date, one API call).
2. For each row with an actual EPS that isn't already recorded in
   `data/earnings_history.jsonl` for that ticker+period (dedup guard):
   a. Look up the ticker's SEC CIK, then fetch its EDGAR year-ago quarter
      (`src/edgar.py`) as the growth baseline.
   b. Read actual EPS and revenue directly off the Finnhub row.
   c. Score EPS growth % and revenue growth % vs. the EDGAR baseline
      (`src/scorer.py`).
   d. Append the new record to `data/earnings_history.jsonl` regardless of
      outcome -- dedup/audit log only, never read back as a baseline.
   e. If both growth checks pass, append to `data/alerts.jsonl` and send a
      Telegram message immediately.

No CIK mapping, or no year-ago quarter found within tolerance, means no
alert for that report -- logged, not silently ignored.

## Invariant
All work must be executable with plain `python src/<name>.py`.
No new dependency on FastAPI or other apps unless requested.

## Conventions
- Use `requirements.txt` for dependencies only.
- Use `data/` for JSONL outputs.
- Do not hardcode credentials. Read from env (`FINNHUB_API_KEY`,
  `TELEGRAM_CHAT_ID`) — never put API keys in `config.yaml` or any tracked file.
- Telegram sending is the Hermes gateway usage here (`hermes send telegram <chat_id> <message>`).
- Keep changes minimal and focused.

## Suggested run
```
* * * * * cd ~/stock-earnings-monitor && python3 src/monitor.py >> logs/cron.log 2>&1
```
