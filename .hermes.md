# Stock Earnings Monitor

## Data contract
This project is a data system for US stock earnings monitoring.
The agent's job is to maintain and advance the data, not the code framework.

- `watchlists/nasdaq_tickers.json` — list of `{ticker, next_earnings_ts, earnings_datetime_utc, report_time_local, timezone_name, earnings_date, call_time}`
- `watchlists/sp500_tickers.json` — list of `{ticker, next_earnings_ts, earnings_datetime_utc, report_time_local, timezone_name, earnings_date, call_time}`
- `data/earnings_history.jsonl`
- `data/upcoming_earnings.jsonl`
- `data/alerts.jsonl`

## Authoritative data sources
### Calendar / next earnings date and exact report time
- Primary: NASDAQ public API via `finance-calendars` style wrapper
  - Endpoint: `https://api.nasdaq.com/api/calendar/earnings?date=YYYY-MM-DD`
  - Fields: `date`, `callTime`, `timeZone`, `epsActual`, `revenueActual`, `epsEstimate`, `revenueEstimate`
- Fallback: `yfinance.Ticker.earnings_dates` when installed

### Actual earnings numbers
- Primary: NASDAQ earnings calendar rows when the report has released actuals
- Secondary: SEC EDGAR filings
  - Use `https://www.sec.gov/cgi-bin/browse-edgar?action=getcompany&CIK={ticker}&type=8-K&dateb=&owner=include&count=40`
  - Find the most recent 8-K filing for earnings and parse exhibit/attachment text for EPS, revenue, period, guidance if present
- Optional: Yahoo Finance / `yfinance` historical tables and `quarterly_financials` when installed

## Data pipelines
### 1. Earnings calendar population / exact datetimes
Use NASDAQ calendar API to find exact report datetimes where available.
Persist `earnings_datetime_utc` plus local metadata into both watchlists.
Build `data/upcoming_earnings.jsonl` from this exact datetime source.

### 2. Upcoming earnings calendar
Extract next exact earnings datetime per ticker.
Persist only entries whose exact datetime is within the lookahead window.

### 3. New report ingestion at scheduled time
When report time arrives, read live report data from NASDAQ first if actuals are present.
Compare new record to prior periods for that ticker.
Flag when criteria are met:
- EPS actual exceeds EPS estimate by >= 5%
- Revenue actual exceeds revenue estimate by >= 1%
Write flags to `data/alerts.jsonl`.

## Invariant
All work must be executable with plain `python src/<name>.py`.
No new dependency on FastAPI or other apps unless requested.

## Conventions
- Use `requirements.txt` for dependencies only.
- Use `data/` for JSONL outputs.
- Use `watchlists/` for static ticker lists.
- Do not hardcode credentials. Read from env or `config.yaml`.
- Telegram sending is the Hermes gateway usage here.
- Keep changes minimal and focused.

## Suggested run order
1. `python src/fetcher.py --populate`
2. `python src/fetcher.py --upcoming`
3. `python src/watcher.py --earliest`
4. `python src/fetcher.py --fetch-reports`
5. `python src/scorer.py --emit-alerts`
6. `python src/alert_telegram.py`
